### ⚠️ Could not complete: container-backed integration tests

Docker **was** present and the daemon **was** reachable, so the instruction's "if Docker is unavailable, skip" branch did not trigger cleanly — the failure is one level deeper: the daemon has no route to the container registry.

Verified directly:

```
$ docker pull postgres:18.1
Error response from daemon: failed to resolve reference "docker.io/library/postgres:18.1":
failed to do request: Head "https://registry-1.docker.io/v2/library/postgres/manifests/18.1":
dial tcp: lookup registry-1.docker.io on 10.69.0.2:53:
read udp 172.17.0.2:34480->10.69.0.2:53: read: connection refused
```

The local image cache is empty, so every Testcontainers image — including the `testcontainers/ryuk` reaper — is unavailable. The two affected classes behave differently:

- **`MySqlIntegrationTests` → 2 skipped.** It declares `@Testcontainers(disabledWithoutDocker = true)`, so the failed Docker probe is swallowed and the class is disabled. This is the desired degradation.
- **`PostgresIntegrationTests` → 1 failed (`initializationError`).** This is the sole build-breaking failure:

  ```
  org.testcontainers.containers.ContainerFetchException:
    Can't get Docker image: RemoteDockerImage(imageName=testcontainers/ryuk:0.13.0, ...)
  Caused by: org.testcontainers.shaded.org.awaitility.core.ConditionTimeoutException
    at org.testcontainers.utility.RyukResourceReaper.maybeStart(RyukResourceReaper.java:78)
    at org.testcontainers.DockerClientFactory.client(DockerClientFactory.java:245)
    at org.testcontainers.junit.jupiter.DockerAvailableDetector.isDockerAvailable(DockerAvailableDetector.java:9)
    at org.testcontainers.junit.jupiter.TestcontainersExtension.evaluateExecutionCondition(TestcontainersExtension.java:166)
  ```

  The class does guard itself with `assumeTrue(DockerClientFactory.instance().isDockerAvailable(), "Docker not available")` in `@BeforeAll`, but the Testcontainers JUnit extension's own availability probe runs *before* that assumption and lets the `ContainerFetchException` escape from `evaluateExecutionCondition`, so the class errors instead of being skipped. Consequence: **`./gradlew test` cannot go green in any environment without container-registry access**, even though nothing is wrong with the code. Worth considering (as a future change — no build or test files were touched by this report) whether `PostgresIntegrationTests` should carry the same `disabledWithoutDocker` treatment as its MySQL counterpart.

**Net read:** the 55 passing tests represent full coverage of the non-container suite. The MySQL and PostgreSQL persistence paths are **unverified**, not broken.
