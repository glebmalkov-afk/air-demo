### Environment notes

These two issues had to be worked around before any build could run. Both are
environment/configuration observations, not code defects — **nothing was changed in
the repository to accommodate them.**

1. **Java 17 toolchain missing.** `build.gradle` declares
   `JavaLanguageVersion.of(17)`, but the runner only had JBR 25 installed, and no
   toolchain download repository is configured. The first invocation failed at
   configuration time:

   ```
   Cannot find a Java installation on your machine (Linux ... amd64) matching:
     {languageVersion=17, vendor=any vendor, ...}
   Toolchain download repositories have not been configured.
   ```

   Resolved for this run by installing Temurin `17.0.20.1+1` outside the repo and
   pointing Gradle at it with
   `-Porg.gradle.java.installations.paths=<jdk>` — a command-line flag only.

2. **Docker daemon up, registry unreachable.** `docker info` succeeds, so
   Testcontainers' `isDockerAvailable()` check passes, but image pulls fail at DNS:

   ```
   failed to resolve reference "docker.io/testcontainers/ryuk:0.13.0":
     Head "https://registry-1.docker.io/v2/...": dial tcp:
     lookup registry-1.docker.io on 10.69.0.2:53: read: connection refused
   ```

   This is worth flagging as a genuine (if minor) robustness gap in the test suite:
   `MySqlIntegrationTests` guards with `@Testcontainers(disabledWithoutDocker = true)`
   and skips cleanly, whereas `PostgresIntegrationTests` guards with
   `assumeTrue(DockerClientFactory.instance().isDockerAvailable(), ...)`. Because that
   assumption only checks whether the *daemon* is reachable — not whether images can
   actually be pulled — the Postgres test **fails** instead of skipping in a
   network-restricted environment. Aligning it with the MySQL test's guard would make
   the suite degrade gracefully offline. *(No change made — source and tests are
   out of scope for this report.)*
