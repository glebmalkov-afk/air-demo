### Three most notable pinned dependencies

**1. Spring Boot — pinned `4.0.3`, newer stable available (`4.0.8` in-line, `4.1.1` latest)**
Declared twice: the Gradle plugin `org.springframework.boot version '4.0.3'`
(`build.gradle:4`) and the `spring-boot-starter-parent` version (`pom.xml:8`). This single
pin transitively governs every `spring-boot-starter-*` dependency in the project, so it is by
far the highest-leverage version here. Five patch releases have shipped in the 4.0.x line
(4.0.4 → 4.0.8), and the current stable minor is 4.1.1 (released 2026-08-20). The 4.0.x patch
bump is the low-risk move and is worth prioritising, since Spring Boot patch releases
routinely carry dependency-level security fixes.

**2. Checkstyle — pinned `12.3.1`, latest stable `14.1.0`**
Set via `ext.checkstyleVersion` (`build.gradle:27`) and `<checkstyle.version>`
(`pom.xml:31`). Two major versions behind; 12.3.1 was the final release of the 12.x line,
with 13.0.0 → 13.11.0 and then 14.0.0 → 14.1.0 (released 2026-08-30) shipped since. Because
style is currently clean, upgrading is safe to attempt but should be expected to surface new
rule violations — major Checkstyle releases add and tighten checks. Note this version is
coupled to `io.spring.javaformat:spring-javaformat-checkstyle` (0.0.47, latest 0.0.48), so
the two should be bumped together rather than independently.

**3. Font Awesome webjar — pinned `4.7.0`, upstream latest `7.3.1`**
`ext.webjarsFontawesomeVersion` (`build.gradle:30`) / `<webjars-font-awesome.version>`
(`pom.xml:28`), consumed as `org.webjars.npm:font-awesome`. This is the most stale pin in the
project by a wide margin — 4.7.0 is the last release of the 4.x line, and upstream is now on
7.x. **This is not a drop-in bump:** Font Awesome changed package identity after 4.x (5.0+
publishes under `@fortawesome/fontawesome-free`, not `font-awesome`), and the icon CSS class
scheme changed from `fa fa-*` to the `fas`/`far`/`fab` style families. Any upgrade therefore
requires re-pointing the webjar coordinate and touching the Thymeleaf templates that
reference icon classes — a deliberate migration, not a version-string edit.
