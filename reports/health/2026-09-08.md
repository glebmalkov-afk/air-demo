### Toolchain note

`build.gradle` requests a Java 17 toolchain, but the only JDK present in this environment
is JBR 25.0.2, and Gradle toolchain auto-provisioning is not configured. The first run
failed at configuration time with:

```
Cannot find a Java installation on your machine matching: {languageVersion=17, ...}
Toolchain download repositories have not been configured.
```

To get an actual test result, a Temurin 17.0.20.1 JDK was downloaded to a temp directory
and passed in via `-Porg.gradle.java.installations.paths=...`. **No build file was
modified** — this was a command-line flag only. If CI ever runs in this image, it will hit
the same wall and needs a JDK 17 on the path or a configured toolchain repository.

### Failing test

**`PostgresIntegrationTests > initializationError`**

```
org.testcontainers.containers.ContainerFetchException: Can't get Docker image:
  RemoteDockerImage(imageName=testcontainers/ryuk:0.13.0, ...)
Caused by: org.testcontainers.shaded.org.awaitility.core.ConditionTimeoutException
  at org.testcontainers.utility.RyukResourceReaper.maybeStart(RyukResourceReaper.java:78)
```

Root cause confirmed by a direct pull attempt:

```
Error response from daemon: failed to resolve reference "docker.io/testcontainers/ryuk:0.13.0":
Head "https://registry-1.docker.io/v2/...": dial tcp: lookup registry-1.docker.io
on 10.69.0.2:53: read udp ...->10.69.0.2:53: read: connection refused
```

This is an environment restriction (no route to Docker Hub), not a regression in the
application. Docker *is* available — the daemon responds to `docker info` — so this could
not be classified as a clean "Docker unavailable, tests skipped" case; the container
runtime is present but cannot fetch images.
