### Testcontainers-dependent tests — ⚠️ could not complete

- `PostgresIntegrationTests` — **failed at initialization** (1 error):
  `org.testcontainers.containers.ContainerFetchException: Can't get Docker
  image: RemoteDockerImage(imageName=testcontainers/ryuk:0.13.0)`, caused by an
  `awaitility` `ConditionTimeoutException`.
- `MySqlIntegrationTests` — **2 tests skipped** (`findAll()`, `ownerDetails()`).
  This class is annotated `@Testcontainers(disabledWithoutDocker = true)`, so it
  degraded gracefully instead of erroring. `PostgresIntegrationTests` lacks that
  guard, which is why it reports as a hard failure rather than a skip.

Root cause, confirmed by a direct pull attempt outside Gradle:

```
$ docker pull testcontainers/ryuk:0.13.0
Error response from daemon: failed to resolve reference
"docker.io/testcontainers/ryuk:0.13.0": failed to do request:
Head "https://registry-1.docker.io/v2/testcontainers/ryuk/manifests/0.13.0":
dial tcp: lookup registry-1.docker.io on 10.69.0.2:53:
read udp 172.17.0.2:56357->10.69.0.2:53: read: connection refused
```

The Docker daemon itself is running and responsive (`docker info` succeeds); it
is DNS resolution to the registry from the daemon's network that is blocked. Per
the report brief, these tests were then excluded from run 2 via a Gradle init
script held in `/tmp` — again, no repository file was changed. **This is an
environment limitation of the automation sandbox, not a regression in the
codebase.** Integration coverage for the MySQL and PostgreSQL profiles remains
unverified for today.
