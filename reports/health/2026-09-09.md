```

`build.gradle` pins `JavaLanguageVersion.of(17)`, but the only JDK on the runner
was the bundled JBR 25.0.2, and no toolchain resolver plugin is configured in
`settings.gradle`, so Gradle could not auto-provision one. Per this report's
rules no build file was modified; instead Temurin 17.0.20.1+1 was downloaded to
a temporary directory and supplied externally via
`-Porg.gradle.java.installations.paths`, after which the build configured and ran
normally. **This is worth noting as a portability finding**: on any machine
without a JDK 17 already installed, `./gradlew test` fails immediately.

### The one failure — environment, not code

`PostgresIntegrationTests > initializationError`

```

  Can't get Docker image: RemoteDockerImage(imageName=testcontainers/ryuk:0.13.0, ...)
Caused by: ConditionTimeoutException: Condition ... was not fulfilled within 2 minutes.
    at org.testcontainers.utility.RyukResourceReaper.maybeStart(RyukResourceReaper.java:78)

A Docker daemon *is* present and responsive on this runner, so the usual
"Docker unavailable" skip path was never taken. What is unreachable is the
container **registry** — DNS for Docker Hub is refused inside the sandbox:

```
$ docker pull hello-world
Error response from daemon: failed to resolve reference

  on 10.69.0.2:53: read: connection refused
```

Testcontainers therefore hangs for two minutes trying to fetch its `ryuk`
sidecar, then reports the container-availability probe as an *error* rather than
as "Docker not available". No application or test logic is implicated.

**Spring Boot 4.0.3 → 4.1.1.** This is the single highest-leverage bump, since
the `io.spring.dependency-management` BOM pins the whole transitive tree
(Spring Framework, Hibernate, Tomcat, Jackson, HikariCP) off it. Staying on the
4.0.x line means missing 4.1.x fixes across all of them. Maven Central also
advertises `4.2.0-M1` as `<latest>`, but that is a milestone and not an upgrade
target. Note that a Boot 4.1 move is the one change here with real blast radius —
it should be a deliberate, separately-tested upgrade, not a drive-by bump.

**Checkstyle 12.3.1 → 14.1.0.** Two major versions behind (13.x and 14.x have
both shipped; 13.8 through 14.1 are all available). Newer Checkstyle majors
routinely add and rename checks, so this upgrade is likely to surface new
violations on first run even though the current configuration is clean — budget
for that rather than expecting a no-op. The pin is duplicated as
`ext.checkstyleVersion` in `build.gradle:27` and `<checkstyle.version>` in
`pom.xml:31`, so both would need to move together to keep Gradle and Maven
builds reporting identically.

**Font Awesome webjar 4.7.0.** `4.7.0` is genuinely the newest artifact published
under `org.webjars.npm:font-awesome`, so a naive "is there a newer version?"
check reports it as current — but that is an artefact of the coordinate being
abandoned, not of the library being up to date. Font Awesome 4.7.0 dates from
2016; the maintained line lives at `org.webjars:font-awesome`, where **7.3.0** is
current. Moving forward is a coordinate change plus an icon-name migration
(FA 4's `fa fa-*` classes were restructured in FA 5+), and every Thymeleaf
template referencing an icon would need updating — so this is flagged as
long-term debt with a real migration cost, not a version-number tweak.

   `PostgresIntegrationTests`, matching `MySqlIntegrationTests:43`. This is the

   moves the entire managed dependency tree.
4. **Bump Checkstyle and spring-javaformat** in `build.gradle` and `pom.xml`
   together, expecting new style findings from the Checkstyle majors.
