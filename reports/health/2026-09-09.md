The Docker daemon **is** present (Server v29.1.3), but the container registry is
not reachable from this runner:


Because Testcontainers cannot pull its `ryuk` reaper image, it treats Docker as
unusable. Per the report's standing instruction to skip Docker/Testcontainers
tests when Docker is unavailable, this failure is **excluded from the health
judgement**. It is a runner networking limitation, not a regression.

### ⚠️ Environment note — Java toolchain

The first `./gradlew test` invocation failed during configuration, before any test ran:

```
Cannot find a Java installation on your machine (Linux ... amd64) matching:
  {languageVersion=17, vendor=any vendor, ...}. Toolchain download repositories have not been configured.
```

`build.gradle` pins `JavaLanguageVersion.of(17)`, but the only JDK on the runner
is JBR 25.0.2, and Gradle toolchain auto-provisioning is not configured. To get a
real test signal without touching any build file, a Temurin 17.0.20.1 JDK was
downloaded to `/tmp/jdk17` and passed in via the command-line property
`-Porg.gradle.java.installations.paths=/tmp/jdk17`. **No build files were modified.**
This will recur on every run until the runner image ships a JDK 17.
