## Build & Tests

### `./gradlew test` — ⚠️ could not complete

The command was run first as specified and failed during project configuration,
before compiling or running any test:

```
* What went wrong:
A problem occurred configuring root project 'spring-petclinic'.
> Failed to calculate the value of task ':compileTestJava' property 'javaCompiler'.
   > Cannot find a Java installation on your machine (Linux 6.17.0-1017-aws amd64) matching:
     {languageVersion=17, vendor=any vendor, implementation=vendor-specific, nativeImageCapable=false}.
     Toolchain download repositories have not been configured.

BUILD FAILED in 24s
```

**Cause.** `build.gradle` requests a Java 17 toolchain:

```groovy
java {
  toolchain {
    languageVersion = JavaLanguageVersion.of(17)
  }
}
```

The only JDK present is `JBR-25.0.2+10-329.111` (`$JAVA_HOME`), and Gradle's
toolchain auto-provisioning is unavailable because no toolchain download
repository is declared in `settings.gradle`. Remediation attempts, none of which
changed any repository file:

- A Gradle init script (`-I`, stored in `/tmp`) retargeting the toolchain to the
  running JVM — ineffective, because `compileTestJava.javaCompiler` is resolved
  at configuration time, before the `projectsEvaluated` hook fires.
- Downloading a JDK 17 from the Adoptium API — blocked by the sandbox proxy
  (`CONNECT tunnel failed, response 403`).
- Extracting a JDK 17 from the `eclipse-temurin:17-jdk` image — blocked, the
  Docker daemon cannot resolve `registry-1.docker.io`.
- Installing an OpenJDK 17 package — no `sudo` and no APT candidate available.

This is an environment/CI-portability gap, not a code defect, but it does mean
the Gradle build is not reproducible on a JDK-25-only machine.
