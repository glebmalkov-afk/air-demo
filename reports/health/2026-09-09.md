## Build & Tests

Command: `./gradlew test`

### First attempt — configuration failure

The run failed before compiling anything:

```
> Failed to calculate the value of task ':compileTestJava' property 'javaCompiler'.
   > Cannot find a Java installation on your machine (Linux 6.17.0-1017-aws amd64) matching:
     {languageVersion=17, vendor=any vendor, ...}. Toolchain download repositories have not been configured.
```

`build.gradle` pins a Java 17 toolchain, the runner only provides JDK 25 (JBR 25.0.2), and no
toolchain resolver is configured in `settings.gradle`, so Gradle cannot auto-provision one.

**Workaround used:** Temurin `17.0.20.1+1` was downloaded to `/tmp/jdk17` and supplied on the command
line via `-Porg.gradle.java.installations.paths=/tmp/jdk17`. **No build file, source file, or test was
modified** — the override is CLI-only and leaves no trace in the repository.

### The one failure — environmental, not a code defect

`org.springframework.samples.petclinic.PostgresIntegrationTests > initializationError`

```
org.testcontainers.containers.ContainerFetchException:
  Can't get Docker image: RemoteDockerImage(imageName=testcontainers/ryuk:0.13.0, ...)
Caused by: org.awaitility.core.ConditionTimeoutException
```

Root cause confirmed by pulling the image directly:

```
$ docker pull testcontainers/ryuk:0.13.0
Error response from daemon: failed to resolve reference "docker.io/testcontainers/ryuk:0.13.0":
  Head "https://registry-1.docker.io/v2/...": dial tcp: lookup registry-1.docker.io on 10.69.0.2:53:
  read udp ...: connection refused
```

So the Docker **daemon is available**, but the **image registry is not reachable** (DNS refused).
Testcontainers therefore cannot function at all in this sandbox. This is a CI/network limitation, not
a regression in the application. Excluding the Testcontainers-dependent suite, **55 of 55 remaining
tests pass**.

### The two skips — intentional, unrelated to Docker

- `MySqlIntegrationTests.findAll()`
- `MySqlIntegrationTests.ownerDetails()`

Both are skipped by the class-level `@DisabledInAotMode` annotation
(`src/test/java/org/springframework/samples/petclinic/MySqlIntegrationTests.java:45`), because the
Gradle `test` task runs with AOT test processing enabled. They would be skipped on a fully networked
runner too.

### The three most notable pins

**1. Spring Boot — `4.0.3` → newer stable available (`4.1.1`)**

Declared in both builds: `id 'org.springframework.boot' version '4.0.3'` (`build.gradle:4`) and the
`spring-boot-starter-parent` `<version>4.0.3</version>` (`pom.xml:8`). This is the single most
consequential pin — it drives the managed versions of nearly every other dependency in the project.
The current stable line is **4.1.x** (latest `4.1.1`); within the 4.0 line itself, `4.0.8` is
available, offering a low-risk patch-only step. A 4.0 → 4.1 move is a minor-version upgrade and
should be treated as a deliberate, tested change rather than a routine bump.

**2. Java toolchain — `17` → newer LTS available (`21`, `25`)**

`build.gradle:19` pins `JavaLanguageVersion.of(17)`; `pom.xml:19` sets `<java.version>17</java.version>`.
Java 17 remains supported LTS, so this is not a risk, but two newer LTS releases have shipped since.
Worth flagging specifically because this pin is what broke the build on this runner: the environment
ships JDK 25 only, and with no toolchain resolver configured the build cannot self-provision a 17.
Adding a toolchain resolver to `settings.gradle` would make the build portable across runners without
changing the target bytecode level.

**3. Checkstyle — `12.3.1` → newer stable available (`14.1.0`), but pinned on purpose**

`ext.checkstyleVersion = "12.3.1"` (`build.gradle:27`) and `<checkstyle.version>12.3.1</checkstyle.version>`
(`pom.xml:31`). Two majors behind current stable. **This pin looks intentional** — commit `c71ccfd`
("Revert checkstyle to latest v12") deliberately stepped back from a newer major. Treat any upgrade
here as a decision that was already made and revisited, not as neglected drift.
