### The one failure — `PostgresIntegrationTests` (environmental)

```
PostgresIntegrationTests > initializationError
org.testcontainers.containers.ContainerFetchException:
  Can't get Docker image: RemoteDockerImage(imageName=testcontainers/ryuk:0.13.0, ...)
Caused by: org.testcontainers.shaded.org.awaitility.core.ConditionTimeoutException:
  Condition with Lambda expression in RemoteDockerImage was not fulfilled within 2 minutes.
```

Root cause is the sandbox network, not the code. The Docker daemon *is* running, but the
image registry is unreachable — DNS for Docker Hub is refused outright:

```
$ docker pull testcontainers/ryuk:0.13.0
dial tcp: lookup registry-1.docker.io on 10.69.0.2:53: read: connection refused
```

**However, there is a real finding underneath the environmental failure.** The two DB
integration tests guard for Docker differently, and only one guard holds up:

- `MySqlIntegrationTests` uses `@Testcontainers(disabledWithoutDocker = true)` and
  **skipped cleanly** (the 2 skipped tests above).
- `PostgresIntegrationTests` guards with an assumption in `@BeforeAll`
  ([PostgresIntegrationTests.java:68](../../src/test/java/org/springframework/samples/petclinic/PostgresIntegrationTests.java)):
  `assumeTrue(DockerClientFactory.instance().isDockerAvailable(), "Docker not available")`.
  That call does not return `false` here — it tries to start the Ryuk reaper container
  first, and *throws* `ContainerFetchException` after a 2-minute timeout. The assumption
  never gets to evaluate, so the class reports `initializationError` instead of skipping.

So the guard protects against "no Docker daemon" but not against "daemon up, registry
unreachable" — which is exactly the shape of a restricted CI network. Per this run's
rules no test was modified; flagging it for a maintainer.
