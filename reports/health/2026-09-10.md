### ⚠️ Environment note (not a repo defect)

The first `./gradlew test` invocation **failed during configuration**, before any
test ran:

```
> Failed to calculate the value of task ':compileTestJava' property 'javaCompiler'.
   > Cannot find a Java installation on your machine matching:
     {languageVersion=17, vendor=any vendor, ...}.
     Toolchain download repositories have not been configured.
```

`build.gradle` requests `JavaLanguageVersion.of(17)`, but the only JDK on this
runner is JBR 25.0.2, and the project configures no toolchain download
repository (no Foojay resolver in `settings.gradle`). The runner's egress proxy
also blocks `api.foojay.io`, `download.java.net` and `corretto.aws`, so Gradle
could not auto-provision one either.

Resolution used for this run: a Temurin 17.0.13+11 JDK was downloaded to `/tmp`
(from `github.com`, which the proxy does allow) and passed to Gradle via
`-Dorg.gradle.java.installations.paths=...`. **No repository file was modified.**
All numbers above come from that successful run.

Worth flagging for maintainers: anyone on a JDK-17-less machine hits this same
wall. Adding the Foojay toolchain resolver plugin to `settings.gradle` would let
Gradle provision the toolchain itself. *(Recommendation only — not applied, as
this report is not permitted to change build files.)*
