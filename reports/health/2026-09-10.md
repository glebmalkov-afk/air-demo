Worth noting for the maintainers: `MySqlIntegrationTests` degrades gracefully when Docker is
unusable, but `PostgresIntegrationTests` does not. Its `assumeTrue(...isDockerAvailable())`
guard in `@BeforeAll` never gets the chance to run, because Testcontainers' own
docker-availability probe throws while trying to pull the `ryuk` sidecar image. A daemon that
is up but cannot reach a registry turns into a hard error rather than a skip. That is a small
robustness gap in an environment like this one.

## Dependencies

### The three most notable pins

**1. Spring Boot — `4.0.3` → latest stable `4.1.1` ⚠️**

Pinned in both `pom.xml` (`spring-boot-starter-parent`) and `build.gradle`
(`org.springframework.boot` plugin). The 4.0.x line has since published 4.0.4 through
**4.0.8**, and the 4.1 minor line is out at **4.1.1**. This is the most consequential gap in
the project: it governs the managed versions of essentially every other runtime dependency,
so eight patch releases of upstream fixes are currently unadopted. Moving to 4.0.8 would be
the low-risk step; 4.1.1 is the fully current option.

**2. Checkstyle — `12.3.1` → latest `14.1.0` (deliberately held) ✅**

`pom.xml` carries an explicit rationale directly above the pin: *"Checkstyle needs to stay on
v12 since v13 sets minimal jdk to 21."* Since the project targets Java 17, that constraint is
still valid, and **12.3.1 is the newest release in the 12.x line** — so the pin is both
intentional and as fresh as it can be. No action needed. This is exactly how a held-back
dependency should be documented.

**3. Font Awesome — `4.7.0`, frozen coordinate ⚠️**

Declared as `org.webjars.npm:font-awesome:4.7.0`. That coordinate reports 4.7.0 as its latest
release, which makes it *look* current, but the underlying npm package was deprecated after
Font Awesome 4 and no longer receives releases — 4.7.0 dates from 2016. Active development
moved to a different artifact: **`org.webjars:font-awesome` is at 7.3.0**. This is not a
version bump so much as a coordinate migration, and it would require icon-class changes in the
Thymeleaf templates, so it is a deliberate piece of work rather than a routine update.
