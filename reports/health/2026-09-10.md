### Worth noting: the two integration tests guard on Docker differently

- `MySqlIntegrationTests` uses `@Testcontainers(disabledWithoutDocker = true)` and is
  **cleanly skipped** (its 2 tests are the 2 skips above).
- `PostgresIntegrationTests` guards with `assumeTrue(DockerClientFactory.instance().isDockerAvailable(), ...)`
  in `@BeforeAll` — but the Testcontainers availability probe *itself* tries to start the
  Ryuk reaper container, so it throws before the assumption can be evaluated. The result is
  a hard `initializationError` instead of a skip.

Because the daemon is up, "Docker is unavailable" style guards do not trigger; only the
*pull* fails. Aligning `PostgresIntegrationTests` with the `disabledWithoutDocker` approach
(or catching the fetch exception in the probe) would make the suite green on restricted
runners. Flagged only — no source or test files were modified by this report.
