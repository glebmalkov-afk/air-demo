The unfiltered `./gradlew test` run (58 tests, 6 m 09 s) ended `BUILD FAILED` with
**1 failure and 2 skips**, all attributable to container images being unavailable:

| Test | Outcome | Cause |
| --- | --- | --- |
| `PostgresIntegrationTests#initializationError` | failed | `org.testcontainers.containers.ContainerFetchException: Can't get Docker image: RemoteDockerImage(imageName=testcontainers/ryuk:0.13.0, ...)` |
| `MySqlIntegrationTests#findAll()` | skipped | `@Testcontainers(disabledWithoutDocker = true)` — Testcontainers judged Docker unusable once the Ryuk sidecar could not be fetched |
| `MySqlIntegrationTests#ownerDetails()` | skipped | same as above |

Root cause, confirmed directly:

```
$ docker pull testcontainers/ryuk:0.13.0
Error response from daemon: failed to resolve reference "docker.io/testcontainers/ryuk:0.13.0":
failed to do request: Head "https://registry-1.docker.io/v2/testcontainers/ryuk/manifests/0.13.0":
dial tcp: lookup registry-1.docker.io on 10.69.0.2:53:
read udp 172.17.0.2:43925->10.69.0.2:53: read: connection refused
```

The Docker daemon is present and responsive (server version **29.1.3**); only image
*pulls* fail, because DNS resolution for the registry is refused in this sandbox.
`PostgresIntegrationTests` carries no `disabledWithoutDocker` guard, so it surfaces as
a hard failure rather than a skip. **This is an infrastructure limitation of the
report runner, not a defect in the repository.** These tests should be exercised in an
environment with registry access before drawing conclusions about the MySQL/PostgreSQL
profiles.

### ⚠️ Note: Java 17 toolchain was missing and had to be provisioned

The first `./gradlew test` attempt failed during configuration after 26 s:

```
> Failed to calculate the value of task ':compileTestJava' property 'javaCompiler'.
   > Cannot find a Java installation on your machine (Linux ... amd64) matching:
     {languageVersion=17, vendor=any vendor, ...}. Toolchain download repositories
     have not been configured.
```

`build.gradle` requires a Java 17 toolchain, but the only JDK on the runner was
JBR 25.0.2, and Gradle's auto-provisioning endpoints (`api.foojay.io`,
`api.adoptium.net`) are blocked by the sandbox proxy. To let the build proceed
*without touching any build file*, Temurin 17.0.9+9 was downloaded from GitHub into
`/tmp/jdks/` and supplied purely as a command-line flag:

```
./gradlew test -Dorg.gradle.java.installations.paths=/tmp/jdks/jdk-17.0.9+9
```

Nothing was written inside the repository to accomplish this, and the same flag was
used for the code-style run. Worth flagging for whoever provisions this runner: a
preinstalled JDK 17 would remove this step.
