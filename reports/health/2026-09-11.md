### ⚠️ Environment caveat (not a repo defect)

The first invocation of `./gradlew test` failed during configuration:

```
Cannot find a Java installation on your machine matching:
  {languageVersion=17, vendor=any vendor, ...}
Toolchain download repositories have not been configured.
```

`build.gradle` requires a Java 17 toolchain, but the runner only had JBR 25 on `PATH` and no
JDK 17 anywhere on disk. Gradle toolchain auto-provisioning is not configured for this project
(no foojay resolver in `settings.gradle`), and `api.foojay.io` / `api.adoptium.net` are both
blocked by the runner's egress proxy.

Resolved without changing any project file: Temurin **17.0.20.1+1** was downloaded from GitHub
into `~/.jdks` and passed to Gradle purely on the command line via
`-Porg.gradle.java.installations.paths=...`. The numbers above come from that run. This is a CI
environment gap, not a problem with the repository — a runner with JDK 17 present needs no such
workaround.
