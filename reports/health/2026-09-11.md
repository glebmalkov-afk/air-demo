### ⚠️ Environment note: missing JDK 17 toolchain

The first two `./gradlew test` invocations **failed before compiling anything**, with a
configuration-time error:

```
> Failed to calculate the value of task ':compileTestJava' property 'javaCompiler'.
   > Cannot find a Java installation on your machine matching:
     {languageVersion=17, ...}. Toolchain download repositories have not been configured.
```

`build.gradle` pins `JavaLanguageVersion.of(17)`, but the only JDK installed on the
runner was **JDK 25** (JBR 25.0.2), and Gradle toolchain auto-provisioning was
unusable because the egress proxy returns **HTTP 403** for every JDK download host
tried (`api.adoptium.net`, `api.foojay.io`, `corretto.aws`, `cdn.azul.com`,
`download.bell-sw.com`, `download.java.net`).

Resolution, with **no repository files changed**: a genuine **Temurin JDK 17.0.20** was
extracted from the reachable `eclipse-temurin:17-jdk` Docker image into `/tmp/jdk17`
and supplied to Gradle via `JAVA_HOME`. The reported run therefore executed on the
Java 17 the build actually asks for — results above are not from a downgraded or
relaxed toolchain. This is a **runner-provisioning gap, not a repository defect**; if
these health runs are to stay reproducible, the runner image should ship a JDK 17 or
the proxy should allow a JDK download host.
